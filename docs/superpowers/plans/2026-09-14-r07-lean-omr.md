# MARKA R07 Lean OMR Implementation Plan

> **For Codex:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Replace the R06 always-on nine-anchor/100-track geometry with an R07 form that scans from four mandatory corner markers, uses four optional edge anchors only when they materially improve deformation correction, and shares 40 timing marks across the answer grid.

**Architecture:** Keep one canonical layout shared by the PDF generator, scanner, and API. Registration first computes a global homography from the four mandatory corners. It compares any detected optional anchors with that global model and activates piecewise correction only when at least two optional anchors are present and their residual exceeds the configured threshold. Timing calibration detects one left and one right mark per answer row, then interpolates the calibrated row position across the five answer columns; missing timing marks fall back to nominal geometry without failing the scan.

**Tech Stack:** Python 3, OpenCV, NumPy, ReportLab, unittest, FastAPI test client

**Step 3: Implement anchor detection and adaptive registration**

In `src/omr_scanner.py`:

- Read required and optional IDs from the sheet registration contract.
- Require exactly the four configured corner IDs, but accept any subset of optional IDs.
- Compute the global destination-to-source homography from required corners.
- Project each available optional canonical point through the global model and calculate its Euclidean residual.
- Use global remapping when fewer than two optional anchors exist or the maximum residual is at most 4 px.
- Use the existing Delaunay/affine piecewise remapping only when both gates are met.
- Include mode, detected required IDs, detected/missing optional IDs, maximum optional residual, and anchor errors in diagnostics.
